# GitHub CLI-oppsett

## 2026-11-11 kl. 18:31

### Oppgave
Sjekke hvilken e-postadresse Git bruker for commits. Installere GitHub CLI fra GitHubs offisielle pakke uten Homebrew, kontrollere installasjonen og logge inn med `gh auth login` på brukerens eksisterende konto. Til slutt føre installasjonen og innloggingen i `docs/arbeidslogg.md`. Git-innstillinger og prosjektfiler skulle ikke endres underveis, og ingenting skulle committes eller pushes. Deretter føre arbeidet med story 1.1 fra 10. november inn i arbeidsloggen, med bare dokumenterte hendelser, og kontrollere endringene for personvern. Til slutt committe og pushe logg- og dokumentasjonsendringene til story-grenen, ikke `main`, uten å endre kode eller Git-innstillinger.

### Plan
- Sjekke om `gh` og Homebrew fantes. Ingen av dem gjorde det.
- Laste ned den offisielle `.pkg`-fila for v2.103.3 fra `cli/cli` til en midlertidig mappe utenfor prosjektet.
- Før installasjonen kontrollere sjekksum, signatur og innhold, uten å kjøre noe fra pakken.
- Åpne installeren, slik at brukeren selv godkjenner med administratorpassordet, og kontrollere etterpå.
- Logge inn med `gh auth login --web` uten spørsmål (`GH_PROMPT_DISABLED=1`), slik at gh ikke setter opp Git-autentisering.
- Ta et fingeravtrykk av Git-konfigurasjonen før og etter innloggingen.

### Resultat
- **E-post:** Git lager adressen selv av brukernavnet og maskinnavnet, fordi `user.email` og `user.name` ikke er satt noe sted. Alle tidligere commits har den samme adressen. Ingenting er endret.
- **Installasjon:** `gh` 2.103.3 ligger i `/usr/local/bin/gh`.
  - Sjekksummen stemmer med GitHubs sjekksumfil.
  - Programmet er gyldig signert av GitHub (Developer ID, team VEKTX9H2N7). Selve `.pkg`-innpakningen er ikke signert.
  - Pakken har ingen installasjonsskript, og alle 238 filene havner under `/usr/local`. Alle finnes, også man-siden.
- **Innlogging:** innlogget på github.com med brukerens konto. Tokenet ligger i nøkkelringen, med rettighetene `repo`, `read:org` og `gist`, og et API-kall som bare leser, fungerer.
  - gh kopierte engangskoden til utklippstavlen.
  - «Configured git protocol» gjaldt bare gh sin egen innstilling (`https`).
- **Uendret:** Git-konfigurasjonen har samme fingeravtrykk før og etter. Prosjektet var uendret før logg-oppdateringen.
- **Logg:** `docs/arbeidslogg.md` har fått oppføringene for 10. og 11. november.
  - Oppføringen for 10. november bygger bare på sesjonsloggen for story 1.1, commitene, triageloggen i spesifikasjonen og `sprint-status.yaml`.
  - Under arbeidet viste triageloggen at sesjonsloggen for 10. november hadde feil tall for review-funnene. Riktig er 14 rettet og 25 avvist, ikke 9 og 30, og tallene er rettet der.
  - Personvernsøket fant ingen treff.
- **Commit og push:** en ny personvernkontroll ga ingen treff. Arbeidsloggen er committet som `91e2a98` og rettelsen i loggen for story 1.1 som `6849f53`. Begge er pushet til grenen `story/1-1-project-skeleton` sammen med denne loggen, ikke til `main`. Ingen kode eller Git-innstillinger er endret.

### Åpne punkter
- Bestemme om Git skal bruke GitHubs noreply-adresse for nye commits. I dag lages adressen av brukernavnet og maskinnavnet, og den vises på GitHub.
